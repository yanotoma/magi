# Magi M1 (Shell) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS tray application that opens a transparent overlay panel on a global hotkey, with no intelligence behind it yet.

**Architecture:** A Tauri v2 shell in Rust hosting a Svelte 5 frontend. Two windows are declared but hidden at startup: `panel` (transparent, undecorated, always-on-top) and `settings` (normal). A tray icon and a global hotkey both toggle the panel. All hardware, model, and network work is out of scope — this milestone proves the shell can live in the background and get out of the way.

**Tech Stack:** Rust (stable, pinned), Tauri v2, Svelte 5, TypeScript, Vite, `tauri-plugin-global-shortcut`, `thiserror`, `tracing`.

**Target version:** `0.1.0-alpha.1`

## Global Constraints

Copied verbatim from the spec and `CLAUDE.md`. Every task's requirements implicitly include this section.

- **All code, comments, documentation, and commit messages are in English.** No exceptions.
- **No `unwrap()` or `expect()` outside tests and `main`'s setup.** A panic in a background tray app is invisible: the hotkey silently stops working, with no window to crash and no terminal to print to.
- **No test may require a GPU, microphone, display, or network.** CI has none of them.
- **Never block the Tauri main thread.**
- `thiserror` enums at module boundaries; `anyhow` at the top level.
- **Arrow functions** in all JavaScript and TypeScript. No `function` declarations.
- **Svelte 5 runes only.** No `export let`, no `$:`, no stores. Runes in shared modules require the `.svelte.ts` extension.
- **Every registered Tauri plugin gets its capability permissions in the same commit.** A plugin missing from a capability file fails at runtime, not compile time.
- **No Claude attribution in commit messages.**
- `main.rs` stays under ~200 lines. Anything larger belongs in a module.
- Target platform is macOS only. Cross-platform code is welcome; cross-platform CI is not in scope.
- Consult `.claude/skills/{rust,tauri-v2,svelte-5}/SKILL.md` before writing code in each area.

## A note on testing this milestone

M1 is mostly platform glue: creating a tray icon and configuring a window are not behaviors that can be meaningfully unit-tested without a display, and CI has none.

Tests in this plan therefore target the three places where real logic exists — shortcut validation, tray state mapping, and version consistency — and every glue task ends with an explicit **manual verification** checklist instead of a fake test. Writing assertions against `TrayIconBuilder` would be test theater; it would pass whether or not an icon ever appeared on screen.

## File Structure

> **Corrected during execution.** The `svelte-ts` template is SvelteKit, not plain Svelte + Vite. That is kept, and it simplifies the frontend: each window points at its own route rather than one page branching on the window label at runtime. Tasks 4 and 7 below reflect the corrected design.

```
magi/
├── package.json                      # version single source of truth
├── .github/workflows/ci.yml          # fmt, clippy, test, svelte-check, build
├── svelte.config.js                  # adapter-static, SPA fallback
├── vite.config.js
├── tsconfig.json
├── static/                           # favicon and other static assets
├── src/                              # SvelteKit frontend
│   ├── app.html
│   ├── app.css                       # global reset; transparent body
│   ├── lib/
│   │   └── shell.svelte.ts           # shared rune state for the shell
│   └── routes/
│       ├── +layout.ts                # ssr = false
│       ├── +page.svelte              # placeholder root
│       ├── panel/+page.svelte        # transparent overlay contents
│       └── settings/+page.svelte     # settings window contents
└── src-tauri/
    ├── Cargo.toml
    ├── tauri.conf.json               # window declarations, version pointer
    ├── build.rs
    ├── capabilities/default.json     # plugin permissions
    ├── icons/                        # app + tray icons
    ├── tests/version_sync.rs         # integration test — needs the lib target
    └── src/
        ├── main.rs                   # three-line entry point
        ├── lib.rs                    # composition root: builder, plugins, setup
        ├── error.rs                  # ShellError
        ├── hotkey.rs                 # validation + registration
        ├── tray.rs                   # tray icon, menu, state mapping
        └── windows.rs                # show/hide/toggle helpers
```

`hotkey.rs`, `tray.rs`, and `windows.rs` are separate files because they fail independently and a reviewer can reject one without the others. `error.rs` is shared because all three produce errors the frontend must be able to distinguish.

**On the `main.rs` / `lib.rs` split:** the template ships it for mobile support, which Magi will never target. It is kept for a different reason — integration tests under `tests/` cannot import from a binary-only crate. `main.rs` calls `magi_lib::run()` and nothing else; `lib.rs` is where the app is assembled.

```rust
//! Guards against the version drifting between manifests.
//!
//! `package.json` is the single source of truth (see docs/VERSIONING.md).
//! `tauri.conf.json` points at it, but `Cargo.toml` carries its own copy for
//! crate metadata and has no way to reference another file — so it can silently
//! fall behind. This test is the only thing that notices.

use std::fs;

fn read_package_json_version() -> String {
    let raw = fs::read_to_string("../package.json").expect("package.json must exist");
    let json: serde_json::Value = serde_json::from_str(&raw).expect("package.json must be valid JSON");
    json["version"]
        .as_str()
        .expect("package.json must have a string version")
        .to_string()
}

fn read_cargo_toml_version() -> String {
    let raw = fs::read_to_string("Cargo.toml").expect("Cargo.toml must exist");
    let manifest: toml::Value = toml::from_str(&raw).expect("Cargo.toml must be valid TOML");
    manifest["package"]["version"]
        .as_str()
        .expect("Cargo.toml must have a package version")
        .to_string()
}

#[test]
fn cargo_and_package_json_versions_agree() {
    assert_eq!(
        read_cargo_toml_version(),
        read_package_json_version(),
        "Cargo.toml and package.json versions have drifted. \
         package.json is the source of truth — see docs/VERSIONING.md."
    );
}

#[test]
fn version_is_the_expected_release() {
    assert_eq!(read_package_json_version(), "0.1.0-alpha.1");
}
```

```rust
/// Errors the shell can produce. Each variant maps to a distinct user-facing
/// surface, which is why this is an enum rather than a string — the caller
/// needs to know whether to show a permissions prompt or a bug report link.
#[derive(Debug, thiserror::Error)]
pub enum ShellError {
    #[error("failed to build the tray icon: {0}")]
    Tray(String),

    #[error("window '{0}' was not found")]
    WindowNotFound(String),

    #[error("shortcut '{shortcut}' could not be registered: {reason}")]
    ShortcutRegistration { shortcut: String, reason: String },

    #[error(transparent)]
    Tauri(#[from] tauri::Error),
}
```

```rust
/// Builds the tray icon and its menu. Called once from `main`'s setup hook.
pub fn init(app: &tauri::App) -> Result<(), ShellError> {
    let open = MenuItemBuilder::with_id("open", "Open Magi").build(app)?;
    let settings = MenuItemBuilder::with_id("settings", "Settings…").build(app)?;
    let quit = MenuItemBuilder::with_id("quit", "Quit Magi").build(app)?;

    let menu = MenuBuilder::new(app)
        .items(&[&open, &settings])
        .separator()
        .items(&[&quit])
        .build()?;

    TrayIconBuilder::with_id("main")
        .menu(&menu)
        // Left click toggles the panel; the menu belongs on right click only.
        .show_menu_on_left_click(false)
        .on_menu_event(|app, event| match event.id().as_ref() {
            "open" => {
                if let Err(e) = crate::windows::toggle_panel(app) {
                    tracing::error!(error = %e, "failed to toggle panel from tray menu");
                }
            }
            "settings" => {
                if let Err(e) = crate::windows::show_settings(app) {
                    tracing::error!(error = %e, "failed to open settings from tray menu");
                }
            }
            "quit" => app.exit(0),
            other => tracing::warn!(id = other, "unhandled tray menu event"),
        })
        .on_tray_icon_event(|tray, event| {
            if let TrayIconEvent::Click {
                button: MouseButton::Left,
                button_state: MouseButtonState::Up,
                ..
            } = event
            {
                if let Err(e) = crate::windows::toggle_panel(tray.app_handle()) {
                    tracing::error!(error = %e, "failed to toggle panel from tray click");
                }
            }
        })
        .build(app)
        .map_err(|e| ShellError::Tray(e.to_string()))?;

    Ok(())
}
```

This references `crate::windows`, which Task 5 creates. It will not compile until then — that is expected and is why Step 8 only runs the unit tests.

```rust
use crate::error::ShellError;
use tauri::{AppHandle, Manager};

pub const PANEL: &str = "panel";
pub const SETTINGS: &str = "settings";

fn window(app: &AppHandle, label: &str) -> Result<tauri::WebviewWindow, ShellError> {
    app.get_webview_window(label)
        .ok_or_else(|| ShellError::WindowNotFound(label.to_string()))
}

pub fn show_panel(app: &AppHandle) -> Result<(), ShellError> {
    let w = window(app, PANEL)?;
    w.show()?;
    w.set_focus()?;
    Ok(())
}

pub fn hide_panel(app: &AppHandle) -> Result<(), ShellError> {
    window(app, PANEL)?.hide()?;
    Ok(())
}

pub fn toggle_panel(app: &AppHandle) -> Result<(), ShellError> {
    let w = window(app, PANEL)?;
    if w.is_visible()? {
        w.hide()?;
    } else {
        w.show()?;
        w.set_focus()?;
    }
    Ok(())
}

pub fn show_settings(app: &AppHandle) -> Result<(), ShellError> {
    let w = window(app, SETTINGS)?;
    w.show()?;
    w.unminimize()?;
    w.set_focus()?;
    Ok(())
}
```

```rust
            // Magi is a background agent: no Dock icon, no app switcher entry.
            #[cfg(target_os = "macos")]
            app.set_activation_policy(tauri::ActivationPolicy::Accessory);

            tray::init(app)?;
            hotkey::register_default(app.handle())?;
            Ok(())
        })
        .on_window_event(|window, event| {
            // Closing a window must never quit a tray app. Hide instead.
            if let WindowEvent::CloseRequested { api, .. } = event {
                api.prevent_close();
                let _ = window.hide();
            }
        })
        .run(tauri::generate_context!())
        .expect("fatal: Tauri failed to start");
}
```

The `expect` here is permitted — it is in `main`'s startup path, where a failure means the app genuinely cannot run and there is no user-facing surface to degrade into.

If `tauri::ActivationPolicy` does not resolve, check the exact path for the installed Tauri version on docs.rs before substituting anything; do not fall back to the frontend `setDockVisibility` API, which runs after the window is created and produces a visible Dock-icon flash on launch.

```rust
use crate::error::ShellError;
use tauri::{AppHandle, Manager};
use tauri_plugin_global_shortcut::{GlobalShortcutExt, ShortcutState};

/// Low conflict rate on macOS, and reachable with one hand.
pub const DEFAULT_SHORTCUT: &str = "Alt+Space";

const MODIFIERS: &[&str] = &[
    "Alt", "Option", "Control", "Ctrl", "Command", "Cmd", "Super", "Meta",
    "Shift", "CmdOrCtrl", "CommandOrControl",
];

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum HotkeyError {
    #[error("shortcut is empty")]
    Empty,

    #[error("shortcut must include at least one modifier")]
    NoModifier,

    #[error("shortcut must include a key, not only modifiers")]
    NoKey,

    #[error("'{0}' is not a recognized modifier or key")]
    UnknownToken(String),
}

fn is_valid_key(token: &str) -> bool {
    // Named keys plus any single alphanumeric character, and F1-F24.
    const NAMED: &[&str] = &[
        "Space", "Enter", "Return", "Tab", "Escape", "Esc", "Backspace", "Delete",
        "Up", "Down", "Left", "Right", "Home", "End", "PageUp", "PageDown",
        "Comma", "Period", "Slash", "Backslash", "Semicolon", "Quote",
        "BracketLeft", "BracketRight", "Minus", "Equal", "Backquote",
    ];

    if NAMED.iter().any(|k| k.eq_ignore_ascii_case(token)) {
        return true;
    }
    if token.len() == 1 && token.chars().all(|c| c.is_ascii_alphanumeric()) {
        return true;
    }
    if let Some(n) = token.strip_prefix('F').or_else(|| token.strip_prefix('f')) {
        if let Ok(num) = n.parse::<u8>() {
            return (1..=24).contains(&num);
        }
    }
    false
}

/// Validates a shortcut string before handing it to the OS.
///
/// This exists because registering a bare key globally is destructive: a
/// shortcut of "Space" swallows the spacebar in every application on the
/// machine, and the user's only recourse is to quit Magi — which they may not
/// be able to do, because typing is broken. Rejecting it here is cheaper than
/// any recovery path.
pub fn validate_shortcut(input: &str) -> Result<(), HotkeyError> {
    let trimmed = input.trim();
    if trimmed.is_empty() {
        return Err(HotkeyError::Empty);
    }

    let tokens: Vec<&str> = trimmed.split('+').map(str::trim).collect();
    let mut modifiers = 0usize;
    let mut keys = 0usize;

    for token in &tokens {
        if MODIFIERS.iter().any(|m| m.eq_ignore_ascii_case(token)) {
            modifiers += 1;
        } else if is_valid_key(token) {
            keys += 1;
        } else {
            return Err(HotkeyError::UnknownToken((*token).to_string()));
        }
    }

    if keys == 0 {
        return Err(HotkeyError::NoKey);
    }
    if modifiers == 0 {
        return Err(HotkeyError::NoModifier);
    }
    Ok(())
}
```

```rust
/// Builds the global-shortcut plugin with Magi's handler attached.
pub fn plugin() -> tauri::plugin::TauriPlugin<tauri::Wry> {
    tauri_plugin_global_shortcut::Builder::new()
        .with_handler(|app, _shortcut, event| {
            // The handler fires on BOTH press and release. Without this filter
            // the panel toggles twice per keypress and appears not to open.
            if event.state() != ShortcutState::Pressed {
                return;
            }
            if let Err(e) = crate::windows::toggle_panel(app) {
                tracing::error!(error = %e, "failed to toggle panel from hotkey");
            }
        })
        .build()
}

/// Registers the default shortcut. A failure here is not fatal — the tray icon
/// remains a working entry point — so it is logged and surfaced rather than
/// aborting startup.
pub fn register_default(app: &AppHandle) -> Result<(), ShellError> {
    register(app, DEFAULT_SHORTCUT)
}

pub fn register(app: &AppHandle, shortcut: &str) -> Result<(), ShellError> {
    validate_shortcut(shortcut).map_err(|e| ShellError::ShortcutRegistration {
        shortcut: shortcut.to_string(),
        reason: e.to_string(),
    })?;

    app.global_shortcut()
        .register(shortcut)
        .map_err(|e| ShellError::ShortcutRegistration {
            shortcut: shortcut.to_string(),
            // The OS does not tell us which application holds the combo, so the
            // message says what we actually know rather than guessing.
            reason: format!(
                "{e} — another application may already own this combination, \
                 or Accessibility permission has not been granted"
            ),
        })?;

    tracing::info!(shortcut, "global shortcut registered");
    Ok(())
}
```
