# M4 — Audio and speech-to-text

**Target version:** `0.3.0-alpha.1`
**Depends on:** M2 (config, Settings), M3 (`Transcriber` has nothing to do with tiers, but the session that will call it does)

## What this milestone is for

The first genuinely useful build. Until now Magi answers what you type, which a browser tab does better. Holding a hotkey and talking is the interaction the whole design exists for — a background agent you address without switching windows.

Everything here runs locally. No audio leaves the machine.

## The constraints that shape it

Two, and they pull in the same direction.

**No test may require a microphone, a GPU, or the network.** Same rule as every milestone, and it bites hardest here because this is the first module whose entire subject is hardware.

**whisper-rs is a C++ dependency.** It shells out to `cmake` and compiles whisper.cpp. That makes it the first compile-time toolchain dependency Magi has taken, and it means the parts worth testing have to be reachable without it.

Together they force the same shape M2 and M3 ended up with: hardware behind a trait, and every decision in a pure function beside it.

## Decisions

### The format contract lives in `audio`, not in `stt`

Whisper needs 16 kHz mono `f32`, and `whisper-rs` does not resample — it converts integers to floats and stereo to mono, then stops. A microphone will not give you 16 kHz; macOS built-in inputs are 48 kHz.

So resampling belongs in `audio`, and `AudioSource` promises 16 kHz mono `f32` as its output type rather than "whatever the device gave us". `stt` then has no opinion about rates at all, and the fake `AudioSource` produces the same thing the real one does — which is what makes a fixture WAV a useful test input rather than a different code path.

Getting this wrong is quiet. Hand Whisper 48 kHz audio and it transcribes confidently and wrongly, because it reads the samples as though they were 16 kHz: speech comes out as gibberish at the wrong speed, with no error.

### Resampling is written by hand, not taken from `rubato`

`rubato` is the obvious choice and does far more than is needed: arbitrary ratios, several interpolation qualities, streaming and fixed-size modes.

What Magi needs is one fixed conversion from a device rate to 16 kHz, of speech, for a model that was trained on 16 kHz speech and is robust to far worse than interpolation error. Linear interpolation with a low-pass is enough, and it is thirty lines that can be tested exactly — output length, rate, and the absence of aliasing on a synthetic tone.

If transcription quality turns out to be limited by resampling rather than by the model, this is the first thing to replace, and `rubato` is where to go. Recording the reason now so that decision is made on evidence rather than re-litigated.

### The recording buffer is capped, and the cap is a behaviour

Push-to-talk has no natural end — a stuck key, a forgotten hotkey, an app that loses focus while held. Unbounded, the buffer grows at 32 kB per second of `f32` at 16 kHz mono, which is slow enough to be invisible and fast enough to matter over hours.

So there is a cap, and reaching it **stops the recording and transcribes what there is** rather than discarding or failing. The user said something; the last thing to do with it is throw it away because they said too much.

### The audio callback does nothing but copy

`cpal`'s data callback runs on an OS realtime thread with a deadline. Allocating, locking, or logging in it causes dropped samples — and the symptom is clicks and gaps that then read as a transcription problem, several layers away from the cause.

So the callback appends into a pre-allocated buffer behind a lock that is never held for longer than a memcpy, and everything else happens on the caller's thread. Resampling included: it is cheap, but it is not realtime-cheap.

### Model download verifies against the API, not the ETag

The `ETag` on HuggingFace's `resolve` URL is 64 hex characters and is **not** the SHA-256 of the file. Verified by downloading `ggml-base.en.bin` and hashing it: the content hash matches `lfs.sha256` from `https://huggingface.co/api/models/ggerganov/whisper.cpp?blobs=true`, and does not match the ETag.

Using the ETag would fail every download on every machine, and the failure would look like a corrupt network rather than a wrong constant.

The download resumes with an HTTP range request. `small.en` is 465 MB; a download that restarts from zero on a dropped connection is a download that never finishes on a bad one.

`base.en` (141 MB) is the default. `medium.en` is 1.4 GB, which is not a first launch.

### whisper-rs is a normal dependency, with `metal` only on macOS

Feature-gating the whole crate so that `cargo test` skips it was tempting — it would keep the test job free of `cmake`. Rejected: a build that compiles the real transcriber only when someone remembers a flag is a build where the real transcriber is usually not compiled, and the first person to find out is a user.

`metal` is target-gated instead, since Metal does not exist on Linux. The Linux CI job compiles whisper.cpp without it, which is slower on a cold cache and correct.

## Order of work

Pure logic first, as before.

1. `audio::format` — resampling, mono folding, the cap. No hardware, exhaustively tested
2. `AudioSource` trait, and the fake that replays a fixture WAV
3. `stt::Transcriber` trait and its fake
4. `cpal` implementation behind `AudioSource`
5. `whisper-rs` implementation behind `Transcriber`, with the build wired up
6. Model download: resume, checksum, progress
7. Settings: model selection, download progress, microphone permission status
8. Push-to-talk: hold the hotkey to record, release to transcribe
9. Panel: recording indicator, transcript appearing in the input

Microphone permission is threaded through from step 4 rather than added at the end. A denied permission is a normal state, not an error path — it has to reach the UI as something explaining what stopped working.
